# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A chess game built with plain HTML, CSS, and vanilla JavaScript. No framework, no
build step, no dependencies. It has two modes — **2-player local (hotseat)** and
**1-player vs an AI with 5 difficulty levels**. The game runs by opening
`index.html` in a browser (served over HTTP so the JS files load).

## Running

There is nothing to build, lint, or install. To preview during development, serve
the folder statically:

```
python -m http.server 8124
```

then open `http://localhost:8124/index.html`. A ready-made config for the Claude
Code preview server lives in `.claude/launch.json` (server name: `chess`).

There is no test suite. Logic is verified by exercising it in the browser — see
the "Verifying" note below.

## Architecture

Three scripts, loaded in order from `index.html` (`chess.js` → `ai.js` → `app.js`):

- **`js/chess.js`** — pure rules engine, **no DOM access**. Exposes everything on
  the global `window.Chess`. Key pieces:
  - Board is an `8×8` array of arrays. Empty square = `null`; a piece is a 2-char
    code: colour (`w`/`b`) + type (`K Q R B N P`), e.g. `"wK"`, `"bP"`. Row 0 =
    rank 8 (Black back rank), row 7 = rank 1 (White). Display orientation is an
    `app.js` concern only.
  - A `position` object is `{ board, turn, castling, ep, halfmove, fullmove }` and
    is **immutable** — `makeMove(pos, move)` returns a new position.
  - `legalMovesFrom` / `legalMoves` filter pseudo-moves that leave the mover in
    check. `isAttacked` / `inCheck` back this and castling legality.
  - `gameStatus(pos, positionKeys)` → `ongoing | check | checkmate | stalemate |
    draw-fifty | draw-material | draw-repetition`. Threefold uses the running
    `positionKeys` list that `app.js` maintains.
  - `toSAN`, `positionKey`, `isInsufficientMaterial`, and a `perft` helper for
    verification round out the API.

- **`js/ai.js`** — search/eval engine, **no DOM access**. Exposes
  `window.ChessAI = { chooseMove, evaluate, LEVELS }`. Negamax with alpha-beta
  pruning, MVV-LVA move ordering, piece-square-table evaluation, and a light
  captures-only quiescence at the top level. `LEVELS` maps difficulty 1–5 to
  `{ depth, jitter, … }`: 1 ≈ random, 5 = depth-4 + quiescence. `chooseMove` is
  called from `app.js` inside a `setTimeout` so the "AI thinking" frame paints
  first.

- **`js/app.js`** — all DOM, state, and interaction, wrapped in an IIFE. A single
  `state` object holds the game; a single `render()` reconciles the 64 pre-built
  square elements against `state` (full re-render every change — no diffing).

- **`css/styles.css`** — board is a CSS grid; squares get `.light`/`.dark`, and
  state is shown purely via class toggles: `selected`, `legal` (+`capture`),
  `last-move`, `check`, plus `piece-white`/`piece-black` colouring of the glyph.

### Key design points

- **Logic/UI separation is deliberate.** Keep all rules in `chess.js` and all
  search in `ai.js` as pure functions; never touch the DOM from either. All
  rendering and events live in `app.js`.
- **`render()` is the single source of UI truth.** To change what the board shows,
  mutate `state` and call `render()` — don't poke at square elements directly.
- **Pieces are Unicode glyphs.** The solid glyph set (♚♛♜♝♞♟) is used for *both*
  colours; white vs black is conveyed entirely by the `piece-white` /
  `piece-black` CSS classes (fill + text-shadow outline). No image assets.
- **Orientation is display-only.** `state.flipped` maps display cells to board
  coords in `toBoard()`; the engine never knows about flipping.
- **Undo** snapshots full state before each move. In 1P it pops back to the
  human's turn (undoing the AI reply too); in 2P it pops one ply.

## PWA

Installable Progressive Web App, same setup as the sibling Sudoku project:

- **`manifest.json`** (root) — name, icons, `display: "standalone"`, theme/bg
  colours matching the CSS variables.
- **`sw.js`** (root) — **network-first** service worker. Precaches all static
  assets on install, but at fetch time it tries the network first and only falls
  back to the cache when offline — so a deploy reaches online visitors without a
  hard refresh. Cache is named `chess-v5`; still **bump the version string** when
  deploying so the old cache is evicted on activate.
- **`icons/`** — `icon.svg` (scalable, also the maskable icon), `icon-192.png`,
  `icon-512.png`. PNGs are generated by `python generate_icons.py` (cairosvg if
  available, otherwise Pillow).

The service worker is registered at the bottom of `index.html`.

## Verifying

No tests — validate in the browser, plus the pure functions on `window.Chess`
from the devtools/preview console:

- **Move generation (perft).** From the start position the legal-move tree node
  counts are known: `Chess.perft(Chess.initialPosition(), 1) === 20`, `=== 400` at
  depth 2, `=== 8902` at depth 3. Matching these confirms castling, en passant,
  and promotion are generated correctly.
- **Rules:** play Fool's mate (→ `checkmate`), force a stalemate, castle both
  sides, perform en passant and a promotion, and reach K-vs-K (→ `draw-material`).
- **AI:** `ChessAI.chooseMove(Chess.initialPosition(), level)` returns a legal
  move for every level 1–5; a level-5 mid-game move should return in ~1s.
